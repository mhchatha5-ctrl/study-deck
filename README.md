# Study Deck

A private study app for your phone. Add your PDFs, mark where questions and
answers start, tick or cross each question, and let the app bring back the ones
you got wrong. It installs to your Home Screen and works offline.

Everything stays on your phone. No account, no server, no analytics.

## What it does

- **Today**: one task and one Start button. Start opens the PDF at the exact
  place you stopped. Due redo items always come first. With an exam date, plan
  phases and a rota, the task is sized to the day (short on work days, longer on
  days off, Quick 5 only when away). **Quick 5** serves redo items and cards for
  short gaps; **Not today** moves the task to tomorrow.
- **Library**: add many PDFs at once and give each a type with one tap
  (Question book, Past paper, Reading). Pages are shown exactly as they are with
  PDF.js, so scanned and handwritten PDFs work too. Pinch or double-tap to zoom.
- **Sections**: tap *Questions start here*, then *Answers start here* (same PDF
  or another) or *Same page*. A section runs until the next one starts. PDF
  bookmarks can become ready-made sections. Topics are optional, one tap.
- **Study view**: one tap flips between questions and answers, keeping your
  place on each side. A draggable cover hides answers on the same page. One tap
  writes a Trigger → Target card from the current question. The screen stays awake.
- **Scoring and redo**: ✓, ✗ and ? log each question by number. Every ✗ or ?
  joins the redo list with the question page and answer page: back in 3 days,
  a tick moves it to 10 days, a tick at 10 days clears it, a cross restarts it.
- **Past papers**: timed mode (1, 2 or 3 hours, or custom); score and time
  taken are saved.
- **Cards**: tap to reveal, *Knew it* or *Missed it*; missed cards come first.
  Audio mode reads cards aloud with the phone's voice, pausing before each target.
- **Rota**: paste an iCal link once; the phone reads it directly each time the
  app opens. If the browser blocks that, import a downloaded `.ics` file, or tap
  days on a calendar. Shift names are labelled once.
- **Progress**: scores by topic and section (weakest first), questions this
  week, days left, timed paper results.
- **Data**: on-device storage only, a request for permanent storage, one-file
  backup and restore with a weekly reminder. App updates never touch your data.

## Install on your phone

Open the app's web address, then:

- **Android (Chrome)**: tap *Install* when offered (or ⋮ › *Add to Home screen*).
- **iPhone (Safari)**: Share › *Add to Home Screen*. Add your PDFs after
  installing, because the Home Screen app keeps its own storage.

## Publish with GitHub Pages

1. On GitHub open the repository, then **Settings › Pages**.
2. Under **Build and deployment › Source**, choose **Deploy from a branch**.
3. Choose the branch that holds this code and the **/ (root)** folder, then **Save**.
4. After a minute or two the app is live at
   `https://<your-user-name>.github.io/<repository-name>/`.

There is no build step: the repository is the website.

## For developers

Plain HTML, CSS and JavaScript modules. PDF.js (legacy build, Apache-2.0) is
vendored in `vendor/pdfjs`.

```sh
node test/server.mjs 8080         # serve locally at http://localhost:8080/
node tools/precache.mjs           # refresh the offline file list in sw.js (run before committing)
npm test                          # generate sample PDFs and run end-to-end tests (Playwright)
node test/e2e.mjs --iphone        # same tests at an iPhone screen size
```

The tests use made-up sample PDFs and a made-up rota generated by
`tools/make-samples.mjs`. Never commit real books, papers or calendars.

Storage rule for future changes: the IndexedDB schema may only add stores, never
remove or clear them (see `js/db.js`), and the service worker only caches app
files.
